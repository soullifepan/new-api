# 本地定制与上游同步治理

状态：已采纳

日期：2026-08-27

## 目标

本仓库以 `upstream/main` 为功能基线，持续获得 New API 的通用能力、修复和安全更新；本地只维护确有业务价值的扩展。避免将单一供应商的特殊接口散落到通用 relay、渠道和前端逻辑中，从而降低每次同步上游时的冲突成本。

## 分支规则

| 分支 | 用途 | 生命周期 |
| --- | --- | --- |
| `main` | 本地可运行的集成基线，承载已验证的本地定制 | 长期保留 |
| `upstream/main` | 官方仓库的只读远程跟踪分支 | 不直接提交 |
| `codex/feature/<topic>` | 新功能，例如 `codex/feature/xfusion-extensions` | 合并后删除 |
| `codex/fix/<topic>` | 缺陷修复 | 合并后删除 |
| `codex/chore/<topic>` | 上游同步、构建或维护任务 | 合并后删除 |
| `codex/experiment/<topic>` | 有明确期限的验证性工作 | 结论确定后删除 |

不再创建长期存在的“备份分支”。需要保留重大实验时，在合并前打带日期和目的的 tag，或先取得明确确认后再归档分支。

历史的、未合并的功能分支不能仅凭名称删除。确认不再需要后，使用者必须明确指定分支名，再执行删除。

## 上游更新流程

1. 先确认工作区干净：`git status --short --branch`。
2. 拉取官方更新：`git fetch upstream main`。
3. `upstream/main` 就是官方快照，不需要额外创建本地“备份分支”。切换到 `main` 后执行 `git merge upstream/main`。
4. 在 `main` 解决本地定制与官方更新的冲突，优先保留官方通用实现；本地定制应迁移到隔离边界，而不是直接覆盖官方代码。
5. 运行受影响的后端/前端构建和测试，再提交集成结果。

开发分支必须从 `main` 创建，并合并回 `main`。当同步需要较多处理时，先创建 `codex/chore/upstream-update-YYYYMMDD` 完成验证，再合并回 `main`。

## 扩展边界

### 优先使用配置

下列需求应优先通过已有后台配置完成，不引入代码分叉：

- 已支持协议下的渠道、模型名映射、分组、优先级和价格。
- 同一对外模型对应多个渠道的故障切换和调度。
- 标准 OpenAI、Claude、Gemini 或已有任务适配器可表达的请求。

### 采用隔离扩展

供应商专属的资源和任务接口应放入明确的扩展边界。推荐的 API 命名空间为：

- `/v1/extensions/xfusion/kling/...`
- `/v1/extensions/xfusion/seedance/...`

这类接口包括 Seedance 素材组、Kling 高级自定义主体、供应商特有的异步任务查询及资产管理。它们不是 OpenAI function tool，也不应伪装成普通聊天模型调用。

扩展必须明确处理：

- 当前用户、API key、分组与渠道的授权。
- 资源和任务的归属，避免用户之间跨任务查询或操作。
- 创建、查询、失败、取消和回调的生命周期。
- 预扣费、最终结算、退款及异常日志；遵守根目录 `AGENTS.md` 的计费安全约束。
- 上游请求/响应转换与错误映射，并保留供应商原始请求 ID 以便排障。

只有当一个能力已被多个供应商共享、能形成稳定通用协议，或必须接入核心统一账务和任务机制时，才把它升级到通用 relay/adapter。升级前先写设计说明并评估对上游合并的影响。

## 实施与验证

1. 先记录供应商的创建、查询、回调和资源管理端点，以及计费单位。
2. 判断该接口是已有配置、已有适配器，还是独立扩展。
3. 在 `codex/feature/<topic>` 分支实现最小完整闭环：鉴权、创建、查询、归属、计费和错误处理。
4. 为请求与响应转换编写确定性的契约测试；对收费模型仅做低成本、可追踪的集成验证。
5. 不提交任何 API key、token、真实用户数据或供应商私有素材 URL。
6. 功能合并后删除工作分支，并在变更说明中写明对上游同步的影响。

## 当前决策

本地优先保持 New API 官方功能完整可更新：`main` 是本地集成目标，`upstream/main` 是可随时比较和回溯的官方快照。未来接入 XFusion/AZOpenAI 等聚合商的非标准视频与素材接口时，先按上述隔离扩展方案设计，不直接修改通用渠道行为；标准模型调用继续优先使用已有渠道、模型映射和价格配置。
